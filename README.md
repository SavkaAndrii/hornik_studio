# Hornik Studio — Custom 3D Printing

Односторінковий сайт на HTML5, CSS3 і JavaScript, без фреймворків, сторонніх бібліотек або етапу збірки. Весь інтерфейс англійською.

## Файли

- `index.html` — єдина HTML-сторінка: навігація, hero, послуги, 4 концептуальні роботи, процес, студія, контактна форма, footer.
- `css/styles.css` — BEM-компоненти, адаптивні сітки, анімації, media queries. На початку `:root` містить кольори, типографіку та відступи.
- `js/main.js` — мобільне меню, фокус клавіатури, активні секції, IntersectionObserver, підтримка reduced motion. Немає мережевих запитів або збереження введених даних.
- `assets/images/` — оптимізовані WebP для сайту та оригінальний PNG-референс із Figma.
- `assets/favicon.svg` — іконка вкладки.
- `images/` і вихідні знімки — попередні матеріали, збережені без змін.

## Локальний перегляд

Відкрийте `index.html` у браузері або виконайте в каталозі проєкту:

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

Потім відкрийте http://127.0.0.1:4173. Для статичного хостингу достатньо `index.html`, `css/`, `js/`, `assets/favicon.svg` та п’яти WebP-файлів із `assets/images/`. Оригінальний `hero-reference.png` для роботи сайту не потрібен. Публікація на хостингу не виконувалася.

## Де редагувати

**Тексти:** безпосередньо в семантичних секціях `index.html`. Збережіть один H1, назви секцій у H2, назви карток у H3. Метадані title, description та Open Graph розміщені в head. Перед публікацією додайте canonical, og:url і абсолютний og:image на справжньому домені.

**Портфоліо:** знайдіть `data-project`. У кожному figure змінюйте src, alt, width/height, заголовок і категорію разом. Зображення зараз концептуальні, а не підтверджені виконані замовлення; відповідні позначки слід прибирати лише після заміни справжніми роботами. Зберігайте локальні WebP, бажано до 1200–1600 px, і lazy loading нижче першого екрана.

**Hero:** `assets/images/hero.webp` походить із наданого Figma-референсу (вузол 4101:2). Референс є плоским зображенням з текстами. CSS-контейнер `.hero__visual` показує праву частину з об’єктом, а заголовки, навігацію і кнопки реалізовано справжніми HTML-елементами. Для подальшої незалежної анімації потрібна окрема модель або чистий рендер об’єкта.

**Контакти та соцмережі:** блок `[data-contact-details]` у footer. Замініть два текстові заповнювачі реальними email/телефоном і посиланнями. Вигаданих адрес і порожніх соціальних посилань немає.

**Форма:** `[data-project-form]`. Зараз це лише інтерфейс: кнопка disabled і type=button, надсилання заблоковано, повідомлень про успіх немає. Після підключення реального backend встановіть type=submit, приберіть disabled, замініть пояснення та обробник submit. Успіх показуйте лише після підтвердження сервера; додайте обробку помилок та доступний статус.

## Подальше розширення

- У `[data-three-mount]` можна підключити Three.js окремим модулем. Зберігайте статичний fallback; запуск і зупинка сцени мають враховувати видимість та prefers-reduced-motion. Зараз бібліотека не завантажується.
- Компоненти header, footer, button, work, service і form можуть використовувати ті самі стилі на майбутніх сторінках. Наразі всі посилання — anchors на цій сторінці.
- Для польської версії винесіть тексти в серверні або build-time словники, встановіть правильний lang і додайте hreflang після появи реальних мовних URL. Контент не залежить від JavaScript, що зберігає доступність та індексацію.
- Для CMS використовуйте записи портфоліо з полями slug, title, category, image, alt і concept; генеруйте поточну семантичну HTML-розмітку. Не потрібно замінювати сайт на SPA.

## Перевірки

Синтаксис JavaScript, локальні ресурси, унікальність id та всі anchor-посилання перевіряються без збірки. Візуальний перегляд виконано у браузері на desktop та mobile; також перевірено завантаження зображень, навігацію і відсутність помилок JavaScript. Остаточне надсилання форми навмисно недоступне.
